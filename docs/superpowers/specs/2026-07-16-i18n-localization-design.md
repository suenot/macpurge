# Локализация MacPurge Desktop

**Дата:** 2026-07-16
**Статус:** утверждено, готово к планированию

## Задача

Приложение полностью англоязычное. Нужна поддержка десяти языков: английский (базовый),
русский, немецкий, французский, испанский, португальский, итальянский, китайский,
японский, корейский.

Весь пользовательский текст сейчас захардкожен в JSX. Пользовательских строк в Rust
нет ни одной, кроме четырех пунктов меню в трее (`desktop/src-tauri/src/tray.rs:26-30`).

## Границы

**Входит:** весь UI десктопа — 18 файлов, ~6.5k строк в `desktop/src`; меню трея;
форматирование чисел и дат.

**Не входит:** CLI (`cli/`) остается англоязычным, хотя и делит конфиг с десктопом.
Лендинг не затрагивается. Языки справа налево не поддерживаются — ни один из
десяти не требует RTL, и закладывать зеркалирование макета сейчас незачем.

## Решения

### Библиотека: react-i18next

Главная причина — плюрализация. Русский требует три формы (`1 файл`, `2 файла`,
`5 файлов`), китайский и японский — ни одной, у остальных свои правила. Это уже
отлажено в i18next для всех десяти локалей.

`next-intl` отвергнут: его ценность в роутинге по локали (`/ru/settings`) и серверных
компонентах. У нас статический экспорт (`output: 'export'`), все страницы `'use client'`,
URL с локалью в десктопном приложении не нужны. Платить сложностью не за что.

Свой `t()` отвергнут: плюрализация, интерполяция и фолбэки — это ровно то, что
пришлось бы писать и отлаживать заново на десяти языках.

### Хранение языка: Rust-конфиг

В `Config` (`cli/src/config.rs`) добавляется поле:

```rust
/// UI language for the desktop app (BCP 47, e.g. "ru"). None = follow the system locale.
#[serde(default)]
pub language: Option<String>,
```

`#[serde(default)]` держит обратную совместимость: существующие `~/.macpurge/config.toml`
читаются без миграции, CLI поле игнорирует.

Не `localStorage`, потому что язык нужен и Rust-стороне для трея. Один источник правды.

Разрешение языка при старте:

1. `config.language` — если задан и поддерживается.
2. Локаль macOS — берется из `navigator.language`, сопоставляется по базовому языку
   (`ru-RU` → `ru`, `zh-Hans-CN` → `zh`).
3. `en` — если перевода нет.

Команды по образцу `set_onboarding_completed` (`desktop/src-tauri/src/commands/config.rs:185`):
`set_language(value: Option<String>)`; текущий язык отдается в `ConfigResponse`.

### Словари

`desktop/src/locales/<lang>.json`, плоские ключи с неймспейсом по странице:
`dev.title`, `settings.language.label`, `sidebar.nav.dashboard`.

Все десять языков бандлятся статически. Суммарно это десятки килобайт в локальном
приложении — ленивая загрузка не окупает своей сложности и мигания непереведенного
UI при старте.

`en.json` — единственный источник ключей. Остальные девять фолбэчатся на него
по ключу, поэтому новый английский текст никогда не ломает сборку, а лишь временно
показывается по-английски.

### Меню трея

Четыре строки (`Show MacPurge`, `Quick Scan`, `Toggle DevTools`, `Quit`) переводятся
на Rust-стороне: `HashMap`-карта или `match` по коду языка в `tray.rs`. Меню
пересобирается при смене языка — событие из фронтенда в Rust.

Дублирование словаря между JS и Rust здесь осознанное: четыре строки не стоят
общего формата и генератора.

### Форматирование

`formatBytes` (`desktop/src/lib/types.ts:157`) собирает строку вручную и всегда
дает английский вид: `34.90 GB`. Переводится на `Intl.NumberFormat` с текущей
локалью — иначе английские числа торчат посреди китайского UI. Единицы (`B`, `KB`,
`MB`, `GB`, `TB`) берутся из словаря.

`formatBytesParts` (`types.ts:176`) сейчас режет результат через `.split(' ')`.
Это ломается на локалях с неразрывным пробелом. Обе функции переписываются
поверх общего внутреннего расчета, возвращающего число и единицу раздельно;
`formatBytes` склеивает, `formatBytesParts` отдает части. `.split()` уходит.

Даты — `Intl.DateTimeFormat` с текущей локалью.

Так как обе функции становятся зависимыми от локали, они получают локаль
параметром или через хук — глобальное состояние внутри `types.ts` не заводится,
чтобы функции оставались чистыми и тестируемыми.

### Переключатель языка

В Settings, готовым themed dropdown из `disk/page.tsx` (коммит 90ccecc), а не
нативным `<select>`. Смена применяется сразу, без перезапуска: i18next меняет язык
реактивно, Rust пересобирает трей.

Названия языков в списке пишутся на самих языках (`Русский`, `日本語`, `Deutsch`) —
пользователь, случайно выбравший незнакомый язык, должен суметь вернуться.

## Архитектура

Три слоя с четкими границами:

**`src/lib/i18n.ts`** — конфигурация i18next, список поддерживаемых языков, функция
разрешения локали (`navigator.language` → поддерживаемый код). Не знает про React
и про Tauri.

**`src/lib/LanguageProvider.tsx`** — React-контекст. При монтировании читает язык
из конфига, применяет к i18next. Отдает текущий язык и `setLanguage`, который пишет
в конфиг, переключает i18next и уведомляет Rust. Единственное место, где связаны
i18next, конфиг и трей.

**Страницы** — используют только `useTranslation()`. Про конфиг и Tauri не знают.

Поток данных при смене языка:

```
Settings dropdown → setLanguage(lang)
  → invoke('set_language')  → config.toml
  → i18n.changeLanguage()   → перерисовка UI
  → invoke('rebuild_tray')  → меню трея
```

## Ошибки

Отказ записи в конфиг не должен ронять UI: язык применяется в i18next в любом
случае, ошибка логируется, выбор просто не переживет перезапуск. Это лучше, чем
неработающий переключатель.

Неизвестный код языка в конфиге (правка файла руками) — фолбэк на системную
локаль, без падения.

Отсутствующий ключ — фолбэк на английский, в дев-режиме предупреждение в консоль.

## Проверка

Ключевое, что нужно проверять автоматически, — не переводы, а инфраструктура:

- Разрешение локали: `ru-RU` → `ru`, `zh-Hans-CN` → `zh`, `xx-XX` → `en`,
  `config.language` перебивает системную локаль.
- Полнота словарей: тест проверяет, что множество ключей каждого из девяти языков
  совпадает с `en.json`. Это ловит и забытый перевод, и опечатку в ключе.
- Плюрализация: `1/2/5` для русского дают три разные формы.
- `formatBytes`: одно и то же число в `en` и `ru` дает разные разделители,
  `formatBytesParts` не зависит от пробела в выводе.

Ручная проверка: запустить приложение, переключить язык в Settings, убедиться,
что UI и трей меняются сразу, перезапустить — язык сохранился.

## Порядок работ

1. Каркас: поле в `Config`, команда `set_language`, `i18n.ts`, `LanguageProvider`,
   `en.json` со всеми ключами.
2. Извлечение строк из 18 файлов в ключи. Параллелится по страницам.
3. Форматирование: `formatBytes`, `formatBytesParts`, даты.
4. Трей.
5. Переключатель в Settings.
6. Перевод `en.json` на девять языков.

Шаг 2 — самый объемный и хорошо делится между агентами по страницам, так как
файлы не пересекаются.
